So, you're thinking about creating a Fluxer bot, huh? Think no further, for this guide will get you up and running in no time. You'll need a few things to follow this guide through:

- A text/code editor (such as [VS Code](https://code.visualstudio.com/)) or an integrated development environment (IDE)
- Some basic programming skills and familiarity with JavaScript/Node.js
- [Node.js](https://nodejs.org/en) (a recent LTS version is fine) installed on your system
- A registered account on the instance you're targeting
- A community (referred to as a guild in the API) that you've created

### Step 4: Mint a bot token

Open your new application and scroll to the **Bot Tokens** section. Bot tokens are named — give this one a name that says where it will run (for example `dev` or `production`), then press **Create token**. You'll be asked to confirm your password (or MFA) first; this is [sudo mode](/introduction/authentication#sudo-mode).

<Note>
  Copy the token now and store it somewhere secure, such as a password manager —
  **it is shown exactly once**. If you lose it, revoke it and mint a new one.
  You can mint several named tokens and revoke each one individually; see
  [Bot tokens](/bots/tokens).
</Note>

### Step 5: Mark the bot as private (optional)

In the **OAuth2 URL Builder** section, check "bot" (you don't need any extra permissions for now) and copy the "Authorize URL."

### Step 9: Write the code and run the bot

We'll use `@fluxer/bot_sdk`, the first-party SDK. It handles the gateway lifecycle (heartbeats, automatic RESUME, reconnect backoff), client-side rate limiting, and typed errors for you — see [the SDK page](/bots/sdk) for everything it does.

<Note>
  `@fluxer/bot_sdk` is not published to npm yet — it lives in the
  [Fluxer monorepo](https://github.com/fluxerapp/fluxer) under
  `packages/bot_sdk`, and you currently consume it from a checkout of the repo
  (see [the SDK page](/bots/sdk#installing) for details). If you'd rather
  `npm install` something today, existing Discord libraries work well against
  Fluxer — see [Using Discord-compatible libraries](/bots/migrating_from_discord_js),
  which walks through this same bot with `@discordjs/core`.
</Note>

The SDK ships as TypeScript source and runs under the [`tsx`](https://tsx.is) runner — that's also how the SDK's first consumer runs in production. Set your project up as described in [Installing the SDK](/bots/sdk#installing), then:

First, store your token from Step 4 in a `.env` file in your project folder:

```
FLUXER_BOT_TOKEN=<your token goes here>
```

Then create a `bot.mts` file, looking like so:

```typescript
import {createClient} from '@fluxer/bot_sdk/src/index';

const token = process.env['FLUXER_BOT_TOKEN'];
if (!token) {
  throw new Error('You forgot the token!');
}

const client = createClient({
  // Your instance's base URL. REST and gateway endpoints are resolved
  // automatically from its /.well-known/fluxer document.
  instanceBaseUrl: 'https://multiverse.forum',
  token,
  tokenType: 'bot',
});

client.on('MESSAGE_CREATE', async (message) => {
  if (message.author.bot) {
    return;
  }

  if (message.content === '!ping') {
    await client.api.sendMessage(message.channel_id, {
      content: 'pong!',
      message_reference: {message_id: message.id},
    });
  }
});

client.on('READY', (data) => {
  console.log(`Logged in as @${data.user.username}`);
});

// Resolves once the first READY arrives; rejects on fatal errors (bad token).
await client.connect();
```

Finally, save this file and run it via `npx tsx --env-file=.env bot.mts`.
